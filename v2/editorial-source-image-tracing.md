# APF V2 원문 및 이미지 역추적 검증 절차

## 원칙
Google News RSS 링크의 리다이렉트 실패는 기사 검증 실패가 아니다. 기사 본문, 사건, 사진 출처를 각각 확인한다. 검색 결과 스니펫만으로 검증 완료 처리하지 않는다. 확인되지 않은 URL, 사실, 이미지는 만들지 않는다.

## 순차 탐색
1. 기사 제목 전체 + 매체명으로 검색하고 언론사 원문을 연다.
2. 실패하면 제목에서 기관명, 행사명, 사업명, 인명, 금액, 날짜를 추출하여 2~4개 핵심어로 재검색한다. 예: '조계종 성찬회 동국대', '성찬회 동국대 장학금', '동국대 성찬회 5000만원'.
3. 기관 공식 홈페이지, 보도자료, 공공기관 게시물과 다른 언론 보도를 비교하여 사건의 동일성, 날짜, 수치, 관계자를 대조한다.
4. 그래도 원문을 찾지 못하면 **사진 역추적 경로**를 시작한다. 기관명 + 행사명 + 사진, 전달식, 포토, 갤러리 등으로 검색한다. 공식 보도자료 사진의 캡션, 파일명, 대체텍스트, 게시일, 출처 표시에서 기사 고유명사와 원문 출처 단서를 추출해 다시 기사 검색을 수행한다.
5. 사진 역추적을 통해 원문 링크를 찾으면 해당 페이지를 열어 본문을 검증한다. 사진만 발견했다면 기사 원문 검증 완료로 표시하지 않는다.
6. 동일 사건의 기발행 여부와 선정 기준을 별도 대조한다.

## 기록 필드
candidate_id, discovery_url, searched_queries, publisher_article_url, official_evidence_urls, corroborating_urls, confirmed_facts, event_key, verification_status, image_source_url, image_asset_url, image_caption, image_rights_note, image_verified, verification_timestamp.

## 상태
- publisher_verified: 언론사 원문 본문과 사실 확인
- official_event_verified: 언론사 원문 미확인, 공식 기관 자료로 사건 사실 확인
- image_lead_only: 사진 단서는 있으나 사건 또는 기사 본문 확인 부족
- unverified: 확인 불충분

사진과 기사 링크는 구분하여 기록한다. 공식 사진은 해당 사건과의 관련성, 이미지 파일의 실제 접근 가능 여부, 이용 가능 조건을 확인한 뒤 HTML에 삽입한다. 다른 사건 사진, AI 생성 이미지, 추정 사진으로 대체하지 않는다. 이미지 탐색 성공은 기사 검증 성공을 의미하지 않는다.

## 실행 위치
GitHub Actions는 기사 수집, 검증 대기 목록 생성, 진단 및 결과 보관을 담당한다. ChatGPT 예약 작업은 다중 검색, 사진 역추적, 원문 열람, 사실 검증, 이미지 확보, HTML 편집을 담당한다. OpenAI API 호출은 추가하지 않는다. GitHub 파일 수정 또는 업로드가 실제로 성공한 경우에만 기록 완료라고 보고한다.
